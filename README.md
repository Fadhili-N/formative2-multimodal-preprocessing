# Multimodal User Authentication & Product Recommendation

**Formative 2 – Multimodal Data Preprocessing** · Machine Learning Pipeline · ALU, 2026 September Term

A command-line system that only gives a product recommendation after it has verified who the user is. A user has to pass **two biometric checks**, face recognition and then voiceprint verification, before the product recommendation model runs. If either check fails, access is denied.

---

## System Flow

```
            ┌──────────────────┐
            │   Face image     │
            └────────┬─────────┘
                     ▼
          ┌─────────────────────┐   unknown face    ┌───────────────┐
          │ Facial Recognition  │ ────────────────▶ │ ACCESS DENIED │
          └──────────┬──────────┘                   └───────────────┘
                     │ recognised member
                     ▼
          ┌─────────────────────┐
          │ Product prediction  │  (request is created, not shown yet)
          └──────────┬──────────┘
                     ▼
          ┌─────────────────────┐   unknown voice / ┌───────────────┐
          │ Voiceprint          │   speaker ≠ face  │ ACCESS DENIED │
          │ Verification        │ ────────────────▶ └───────────────┘
          └──────────┬──────────┘
                     │ approved voice
                     ▼
          ┌─────────────────────┐
          │ Display recommended │
          │ product             │
          └─────────────────────┘
```

**Multimodal decision rule.** A recommendation is shown only if all of the following are true:

1. The face model's confidence is at or above its threshold, so the face belongs to a known member.
2. The voice model's confidence is at or above its threshold, so the voice belongs to a known member.
3. The speaker the voice model identifies is the **same person** the face model identified. This stops one member's face from being paired with another member's voice.

## Repository Structure

The repository is organised **by modality**. Each folder holds its own data, scripts, saved model, plots and working notebook, and `main.py` at the root connects them.

```

│

│   ├── models/                     # product_model.pkl
│   ├── plots/

│   ├── raw/                        # <name>_neutral.jpg, <name>_smiling.jpg, <name>_surprised.jpg
```

## Naming Conventions

| Asset | Pattern | Example |
|---|---|---|
| Face images | `<name>_<expression>.jpg` | `diane_smiling.jpg` |
| Augmented images | `<name>_<expression>_<aug>.jpg` | `diane_smiling_rot15.jpg` |
| Audio recordings | `<name>_<phrase>.wav` | `diane_yes_approve.wav` |
| Phrases | `yes_approve`, `confirm_transaction` | |
| Expressions | `neutral`, `smiling`, `surprised` | |
| Member names | lowercase first name | `armstrong`, `ayomide`, `fadhili`, `diane` |

The same lowercase member name is used as the class label in the face model, in the voice model and in the CLI's member-to-customer mapping.

## Model Interfaces (used by `main.py`)

Each model script exposes one function. `main.py` only calls these functions, so a new input goes through **exactly the same feature extraction** that was used in training.

| Module | Function | Returns |
|---|---|---|
| `images/face_model.py` | `verify(image_path)` | `(accepted: bool, member: str, confidence: float)` |
| `audio/voice_model.py` | `verify(audio_path)` | `(accepted: bool, member: str, confidence: float)` |
| `data/product_model.py` | `predict(customer_id)` | `product_category: str` |

Saved models are dictionaries written with `joblib`. Each one contains the fitted model, the ordered list of feature names, the class labels and the acceptance threshold.

## Usage

### 1. Rebuild features and retrain models (optional, the trained models are already committed)

```bash
python data/product_model.py train
python images/face_model.py train

python audio/audio_pipeline.py      # regenerate augmented audio + audio_features.csv
python audio/voice_model.py train
```

### 2. Run the authentication CLI

```bash
python main.py
```

The app asks for a face image and then for a voice sample. The paths below are examples taken from the repository:

| Scenario | Face input | Voice input | Expected result |
|---|---|---|---|
| Full transaction | `images/raw/diane_neutral.jpg` | `audio/converted/diane_yes_approve.wav` | Product recommendation shown |
| Unauthorized face | `images/unauthorized/<file>.jpg` | – | Denied at the face step |
| Unauthorized voice | `images/raw/diane_neutral.jpg` | `audio/unauthorized/stranger_tts1.wav` | Denied at the voice step |
| Face / voice mismatch | `images/raw/diane_neutral.jpg` | `audio/converted/fadhili_yes_approve.wav` | Denied, speaker does not match face |

## Model Results

| Model | Algorithm | Evaluation | Accuracy | F1 (macro) | Log-loss |
|---|---|---|---|---|---|
| Facial recognition | – | – | – | – | – |
| Voiceprint verification | Logistic Regression | Leave-one-recording-out | 0.875 | 0.867 | 0.467 |
| Product recommendation | – | – | – | – | – |

The voice model was chosen over Random Forest, which scored 0.750 accuracy, 0.650 F1 and 1.049 log-loss. All augmented copies of a recording are kept on the same side of each split, so the scores are not inflated by near-duplicates.
